## Objective

Prove that an authenticated Administrator can create one project with a stable
key, that the new project becomes the current context, and that exactly one
attributable creation event is recorded.

## Preconditions

- The isolated local staging candidate is identified by
  `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-ADMIN-NO-PROJECT` is prepared and verified.
- The browser has a fresh profile with no Apistra cookies or storage.
- `STAGING_ADMIN_PASSWORD` and `STAGING_SIGN_IN_URL` are available.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** DSN-001 has page title `Sign in`.
2. **Action (Logged-out visitor):** Enter the fixture username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in` once.
   **Test data:** visible action `Sign in`
   **Expected result:** DSN-003 has page title `Project overview` and offers `Create project`.
5. **Action (Administrator):** Select `Create project`.
   **Test data:** visible action `Create project`
   **Expected result:** DSN-004 has page title `Project creation` and renders `Project name`, `Project key`, `Create project`, and `Cancel`.
6. **Observation (Administrator):** Inspect the initial primary-action state.
   **Test data:** primary action `Create project`
   **Expected result:** `Create project` is disabled while both required fields are empty.
7. **Action (Administrator):** Enter the project name.
   **Test data:** `Atlas Research`
   **Expected result:** `Project name` contains exactly `Atlas Research` and `Create project` remains disabled.
8. **Action (Administrator):** Enter the project key.
   **Test data:** `ATLAS`
   **Expected result:** `Project key` contains exactly `ATLAS` and `Create project` becomes enabled.
9. **Action (Administrator):** Select `Create project` once.
   **Test data:** visible action `Create project`
   **Expected result:** DSN-003 has page title `Project overview` and `Current project` is `Atlas Research`.
10. **Observation (Administrator):** Inspect the current project identifier.
    **Test data:** project key `ATLAS`
    **Expected result:** The overview renders project key `ATLAS` in the selected project context.
11. **Action (Administrator):** Select `Audit`.
    **Test data:** navigation item `Audit`
    **Expected result:** DSN-020 has page title `Audit log`.
12. **Observation (Administrator):** Inspect the newest project-creation event.
    **Test data:** event label `project.created`
    **Expected result:** Exactly one event shows actor `admin.alpha`, project key `ATLAS`, a UTC timestamp, and a correlation ID.

## Cleanup

Restore `FX-PRC-01-ADMIN-NO-PROJECT` through the authorised fixture reset
command and record its receipt. Do not delete the project manually.

## Required evidence and oracle

- screenshots of steps 5, 9, and 12 without credential or session material;
- candidate/environment/fixture identities, browser/version, tester, UTC
  start/end, and attempt;
- created project identifier plus audit-event identifier/correlation ID;
- pass only if one `ATLAS` project is current and exactly one matching audit
  event exists.
