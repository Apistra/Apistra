## Objective

Prove that explicit sign-out revokes the active session and that a subsequent
request to a protected project URL returns to sign-in instead of reusing it.

## Preconditions

- The isolated local staging candidate is identified by
  `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-ISOLATION` is prepared and verified.
- The browser has a fresh profile with no Apistra cookies or storage.
- `STAGING_ADMIN_PASSWORD`, `STAGING_SIGN_IN_URL`, and the authorised project
  URL for `11111111-1111-4111-8111-111111111111` are available.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** DSN-001 has page title `Sign in`.
2. **Action (Logged-out visitor):** Enter the fixture username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in` once.
   **Test data:** visible action `Sign in`
   **Expected result:** DSN-003 has page title `Project overview` and `Current project` is `Atlas Research`.
5. **Action (Administrator):** Open `Administrator menu`.
   **Test data:** accessible name `Administrator menu`
   **Expected result:** The menu renders `Installation status` and `Sign out`.
6. **Action (Administrator):** Select `Sign out` once.
   **Test data:** visible action `Sign out`
   **Expected result:** DSN-001 has page title `Sign in` and no project metadata is rendered.
7. **Action (Logged-out visitor):** Navigate directly to the previously authorised project URL.
   **Test data:** project ID `11111111-1111-4111-8111-111111111111`
   **Expected result:** DSN-001 renders `Your session has expired. Sign in again.` and no project metadata.
8. **Action (Logged-out visitor):** Enter the fixture username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
9. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
10. **Action (Logged-out visitor):** Select `Sign in` once.
    **Test data:** visible action `Sign in`
    **Expected result:** DSN-003 has page title `Project overview` and `Current project` is `Atlas Research`.
11. **Action (Administrator):** Select `Audit`.
    **Test data:** navigation item `Audit`
    **Expected result:** DSN-020 has page title `Audit log`.
12. **Observation (Administrator):** Inspect the newest session-revocation event.
   **Test data:** event label `session.revoked`
   **Expected result:** Exactly one event for the tested sign-out shows actor `admin.alpha`, a UTC timestamp, and a correlation ID.

## Cleanup

Sign out from the new session, close the browser profile, restore
`FX-PRC-01-ISOLATION`, and record the fixture reset receipt.

## Required evidence and oracle

- screenshots of steps 6, 7, and 12 without cookie or token values;
- candidate/environment/fixture identities, browser/version, tester, UTC
  start/end, and attempt;
- pass only if the old session cannot render the protected project and exactly
  one attributable revocation event exists for the tested sign-out.
