## Objective

Prove that a fresh installation creates exactly one bootstrap Administrator,
does not disclose the password, enters an authenticated session, and records an
attributable bootstrap audit event.

## Preconditions

- The isolated local staging candidate is identified by
  `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-FRESH` is prepared and its revision/checksum is recorded.
- The browser has a fresh profile with no Apistra cookies or storage.
- The tester can resolve `STAGING_SIGN_IN_URL`.
- The secret `STAGING_ADMIN_PASSWORD` is available through the protected test
  parameter store and is not copied into notes, screenshots, or logs.

## Procedure

1. **Action (Bootstrap visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** DSN-001 has page title `Sign in` and renders the `Create Administrator` action.
2. **Action (Bootstrap visitor):** Select `Create Administrator`.
   **Test data:** visible action `Create Administrator`
   **Expected result:** DSN-002 has page title `Bootstrap Administrator` and renders `Username`, `Password`, and `Confirm password`.
3. **Action (Bootstrap visitor):** Enter the bootstrap username.
   **Test data:** `admin.bootstrap`
   **Expected result:** `Username` contains exactly `admin.bootstrap`.
4. **Action (Bootstrap visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
5. **Action (Bootstrap visitor):** Enter the same protected password in `Confirm password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Confirm password` displays only masked characters.
6. **Action (Bootstrap visitor):** Select `Create Administrator` once.
   **Test data:** visible action `Create Administrator`
   **Expected result:** DSN-003 has page title `Project overview` and `Administrator menu` is available.
7. **Observation (Administrator):** Inspect the `Current project` region without opening another page.
   **Test data:** accessible name `Current project`
   **Expected result:** The empty state is shown and offers `Create project`; no project is selected.
8. **Action (Administrator):** Open `Administrator menu`.
   **Test data:** accessible name `Administrator menu`
   **Expected result:** The menu renders `Installation status` and `Sign out`.
9. **Action (Administrator):** Select `Installation status`.
   **Test data:** visible action `Installation status`
   **Expected result:** The view renders `Administrator bootstrap is complete.` and no password value or bootstrap creation form.
10. **Action (Administrator):** Select `Audit`.
    **Test data:** navigation item `Audit`
    **Expected result:** DSN-020 has page title `Audit log`.
11. **Observation (Administrator):** Inspect the newest bootstrap event.
    **Test data:** event label `administrator.bootstrap.completed`
    **Expected result:** Exactly one event shows actor `admin.bootstrap`, a UTC timestamp, a correlation ID, and the installation identifier.

## Cleanup

Restore `FX-PRC-01-FRESH` through the authorised fixture reset command and
record the reset receipt. Do not delete the Administrator manually.

## Required evidence and oracle

- screenshot of steps 1, 6, 9, and 11 with no password or session token;
- candidate SHA, environment ID, fixture revision/checksum, browser/version,
  tester, UTC start/end, and attempt;
- captured bootstrap audit-event identifier and correlation ID;
- pass only if every expected result matches exactly and one attributable event
  exists; otherwise fail and record the first mismatching step.
