## Objective

Prove that a stale policy draft cannot overwrite a newer revision and that its
valid unsaved input remains available for comparison and deliberate recovery.

## Preconditions

- The unchanged CAP-02 staging candidate is identified by `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-CAP02-CONFLICT` is applied with opened revision `4`, current
  revision `5`, and unsaved valid `Maximum calls` value `12`.
- A fresh browser profile resolves `STAGING_SIGN_IN_URL` and protected parameter
  `STAGING_ADMIN_PASSWORD`.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** The page title is `Sign in`.
2. **Action (Logged-out visitor):** Enter the Administrator username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in`.
   **Test data:** visible action `Sign in`
   **Expected result:** The page title is `Project overview`.
5. **Action (Administrator):** Select project `Atlas Research`.
   **Test data:** project key `ATLAS`
   **Expected result:** `Atlas Research` is displayed as the current project.
6. **Action (Administrator):** Select navigation item `Limits & Policies`.
   **Test data:** visible navigation label `Limits & Policies`
   **Expected result:** The page title is `Limits and policies`.
7. **Action (Administrator):** Open the fixture-prepared stale policy draft.
   **Test data:** resolved `CAP02_STALE_POLICY_DRAFT_URL`
   **Expected result:** The draft displays base revision `4` and `Maximum calls` value `10`.
8. **Action (Administrator):** Replace `Maximum calls` with the valid unsaved value.
   **Test data:** `12`
   **Expected result:** `Maximum calls` contains exactly `12`.
9. **Action (Administrator):** Select `Save policy draft`.
   **Test data:** visible action `Save policy draft`
   **Expected result:** The message is `This draft changed elsewhere. Reload the latest version before saving.`
10. **Observation (Administrator):** Inspect `Maximum calls` after the conflict.
    **Test data:** expected unsaved value `12`
    **Expected result:** The field still contains exactly `12`.
11. **Observation (Administrator):** Inspect the persisted current policy version.
    **Test data:** current revision `5`
    **Expected result:** Revision `5` remains unchanged and no revision `6` exists.
12. **Action (Administrator):** Select `Reload latest version`.
    **Test data:** visible action `Reload latest version`
    **Expected result:** The latest revision opens with the retained value `12` available for comparison.

## Cleanup

Restore the named fixture snapshot through the authorised CAP-02 reset command
and retain its reset receipt.

## Required evidence and oracle

- screenshots of steps 7, 9, 10, and 12;
- safe conflict audit identifier and before/after revision metadata;
- candidate SHA, fixture checksum, environment, tester, UTC times, and attempt;
- pass only if no silent overwrite occurs and valid unsaved input is retained.
