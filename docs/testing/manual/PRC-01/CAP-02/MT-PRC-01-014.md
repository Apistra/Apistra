## Objective

Prove that the five CAP-02 administration pages preserve navigation, content,
focus, safe messages, permission behavior, and session recovery across the
approved desktop, mobile, keyboard, and 200-percent zoom states.

## Preconditions

- The unchanged CAP-02 staging candidate is identified by `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-CAP02-UI` is applied with its desktop, mobile, and zoom profiles.
- The browser can emulate `1440×900`, `390×844`, and 200-percent zoom and has a
  fresh profile resolving `STAGING_SIGN_IN_URL`.
- `STAGING_ADMIN_PASSWORD` resolves only in the protected execution context.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** The page title is `Sign in`.
2. **Action (Logged-out visitor):** Enter the Administrator username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in`.
   **Test data:** visible action `Sign in`
   **Expected result:** The page title is `Project overview`.
5. **Action (Administrator):** Select project `Atlas Research`.
   **Test data:** project key `ATLAS`
   **Expected result:** `Atlas Research` is displayed as the current project.
6. **Action (Administrator):** Set the browser viewport to the desktop profile.
   **Test data:** `1440×900`
   **Expected result:** Persistent project navigation is visible without horizontal page scroll.
7. **Action (Administrator):** Traverse the CAP-02 navigation by keyboard.
   **Test data:** navigation labels from `FX-PRC-01-CAP02-UI`
   **Expected result:** Every navigation item receives visible focus in DOM order.
8. **Action (Administrator):** Open `Secrets` with the keyboard.
   **Test data:** navigation label `Secrets`
   **Expected result:** `Secret references` opens and focus moves to the page heading or primary content.
9. **Action (Administrator):** Open `Model Endpoints` with the keyboard.
   **Test data:** navigation label `Model Endpoints`
   **Expected result:** `Model endpoints` opens with `Add endpoint` keyboard reachable.
10. **Action (Administrator):** Open `Agents` with the keyboard.
    **Test data:** navigation label `Agents`
    **Expected result:** `Agent versions` opens with exact version references readable without colour dependence.
11. **Action (Administrator):** Open `Tools` with the keyboard.
    **Test data:** navigation label `Tools`
    **Expected result:** `Tools` opens and protected effect classes include text labels.
12. **Action (Administrator):** Open `Limits & Policies` with the keyboard.
    **Test data:** navigation label `Limits & Policies`
    **Expected result:** `Limits and policies` opens and every unit/currency label is programmatically associated with its field.
13. **Action (Administrator):** Set the browser viewport to the mobile profile.
    **Test data:** `390×844`
    **Expected result:** Project navigation becomes a labelled menu and catalogue cards replace wide tables.
14. **Observation (Administrator):** Inspect the mobile primary-action order.
    **Test data:** current CAP-02 page primary action
    **Expected result:** The primary action occurs after page content in DOM order and remains keyboard reachable.
15. **Action (Administrator):** Set browser zoom to 200 percent.
    **Test data:** fixture profile `zoom-200`
    **Expected result:** Content reflows without horizontal page scroll or loss of controls.
16. **Action (Administrator):** Trigger one fixture-prepared validation error.
    **Test data:** empty required field on the current page
    **Expected result:** Focus moves to the invalid field and an accessible live region announces the exact safe error.
17. **Action (Administrator):** Open the foreign-project CAP-02 route.
    **Test data:** resolved `ORION_CAP02_ROUTE`
    **Expected result:** A project-not-found/permission state appears without foreign catalogue metadata.
18. **Action (Administrator):** Expire the current session through the authorised fixture control.
    **Test data:** resolved `CAP02_EXPIRE_SESSION_CONTROL`
    **Expected result:** The next protected navigation returns to `Sign in` with no secret or internal diagnostic.

## Cleanup

Restore the browser profile, viewport settings, session fixture, and named
product snapshot. Retain the reset receipts and secret-free screenshots.

## Required evidence and oracle

- desktop, mobile, and 200-percent zoom screenshots for representative pages;
- keyboard/focus trace, accessible-name/status evidence, and safe error text;
- permission and expired-session screenshots without foreign or secret data;
- pass only if every state remains operable, readable, safe, and WCAG-2.2-AA compatible.
