## Objective

Prove that endpoint saving is offline and an explicit connection test performs
only a bounded read-only probe with a normalised, credential-safe result.

## Preconditions

- The unchanged CAP-02 staging candidate is identified by `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-CAP02-ENDPOINTS` and its local synthetic probe service are applied.
- Probe counters are reset and the fixture receipt records the allowed local destination.
- A fresh browser profile resolves `STAGING_SIGN_IN_URL`; protected parameters
  resolve `STAGING_ADMIN_PASSWORD` and the referenced endpoint credential.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** The page title is `Sign in`.
2. **Action (Logged-out visitor):** Enter the Administrator username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in`.
   **Test data:** visible action `Sign in`
   **Expected result:** The page title is `Project overview`.
5. **Action (Administrator):** Select project `Atlas Research`.
   **Test data:** project key `ATLAS`
   **Expected result:** `Atlas Research` is displayed as the current project.
6. **Action (Administrator):** Select navigation item `Model Endpoints`.
   **Test data:** visible navigation label `Model Endpoints`
   **Expected result:** The page title is `Model endpoints`.
7. **Action (Administrator):** Select `Add endpoint`.
   **Test data:** visible action `Add endpoint`
   **Expected result:** The endpoint form displays all fields defined by DSN-005.
8. **Action (Administrator):** Enter the endpoint name in `Name`.
   **Test data:** `local-llm`
   **Expected result:** `Name` contains exactly `local-llm`.
9. **Action (Administrator):** Select the endpoint purpose.
   **Test data:** `Generative`
   **Expected result:** `Purpose` displays `Generative`.
10. **Action (Administrator):** Select the provider protocol.
    **Test data:** `OpenAI-compatible`
    **Expected result:** `Provider protocol` displays `OpenAI-compatible`.
11. **Action (Administrator):** Enter the allowed local base URL.
    **Test data:** `http://127.0.0.1:18080/v1`
    **Expected result:** `Base URL` contains exactly the supplied URL.
12. **Action (Administrator):** Enter the model identifier.
    **Test data:** `synthetic-chat`
    **Expected result:** `Model identifier` contains exactly `synthetic-chat`.
13. **Action (Administrator):** Select the project secret reference.
    **Test data:** `provider-primary`
    **Expected result:** `Secret reference` displays only `provider-primary` and no secret value.
14. **Action (Administrator):** Select the network profile.
    **Test data:** `Local`
    **Expected result:** `Network profile` displays `Local`.
15. **Action (Administrator):** Select `Save endpoint`.
    **Test data:** visible action `Save endpoint`
    **Expected result:** The endpoint is saved without displaying a connection outcome.
16. **Observation (Administrator):** Inspect the fixture probe counter after saving.
    **Test data:** resolved `CAP02_PROBE_COUNTER_URL`
    **Expected result:** The counter remains exactly `0`.
17. **Action (Administrator):** Select `Test connection` once.
    **Test data:** visible action `Test connection`
    **Expected result:** The action reads `Testing…` and cannot be selected again while the probe is active.
18. **Observation (Administrator):** Inspect the completed connection status.
    **Test data:** endpoint `local-llm`
    **Expected result:** The live status is `Connection verified` without provider payload or credential content.
19. **Action (Administrator):** Test the fixture-prepared metadata-address endpoint.
    **Test data:** `http://169.254.169.254/latest/meta-data`
    **Expected result:** The status is `Destination blocked` and the message is `Destination blocked by network policy.`
20. **Observation (Administrator):** Inspect the fixture probe counter after the blocked request.
    **Test data:** resolved `CAP02_PROBE_COUNTER_URL`
    **Expected result:** The counter increased only for the allowed read-only probe and not for the blocked destination.

## Cleanup

Stop the synthetic probe service, restore the named fixture snapshot, and
retain both reset receipts. Do not retain provider request or credential data.

## Required evidence and oracle

- screenshots of steps 15, 17, 18, and 19 with safe diagnostics;
- before/after synthetic probe counters and safe request-method evidence;
- candidate SHA, fixture checksum, environment, tester, UTC times, and attempt;
- pass only if save is offline, the allowed probe is bounded/read-only, and the forbidden destination is blocked before contact.
