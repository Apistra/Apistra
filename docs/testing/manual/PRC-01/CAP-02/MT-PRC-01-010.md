## Objective

Prove that an agent version publishes with exact primary, fallback, tool-set,
and limits-policy references and cannot be changed in place.

## Preconditions

- The unchanged CAP-02 staging candidate is identified by `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-CAP02-CATALOG` is applied with both compatible endpoints,
  `research-readonly@2`, and `interactive-default@4`.
- A fresh browser profile resolves `STAGING_SIGN_IN_URL` and protected parameter
  `STAGING_ADMIN_PASSWORD`.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** The page title is `Sign in`.
2. **Action (Logged-out visitor):** Enter the Administrator username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in`.
   **Test data:** visible action `Sign in`
   **Expected result:** The page title is `Project overview`.
5. **Action (Administrator):** Select project `Atlas Research`.
   **Test data:** project key `ATLAS`
   **Expected result:** `Atlas Research` is displayed as the current project.
6. **Action (Administrator):** Select navigation item `Agents`.
   **Test data:** visible navigation label `Agents`
   **Expected result:** The page title is `Agent versions`.
7. **Action (Administrator):** Select `Create agent version`.
   **Test data:** visible action `Create agent version`
   **Expected result:** The agent-version form is displayed.
8. **Action (Administrator):** Enter the agent name in `Agent name`.
   **Test data:** `Research Analyst`
   **Expected result:** `Agent name` contains exactly `Research Analyst`.
9. **Action (Administrator):** Enter the instructions in `Instructions`.
   **Test data:** `Summarise cited research evidence.`
   **Expected result:** `Instructions` contains exactly the supplied text.
10. **Action (Administrator):** Select the primary endpoint.
    **Test data:** `local-llm`
    **Expected result:** `Primary endpoint` displays `local-llm`.
11. **Action (Administrator):** Select the fallback endpoint.
    **Test data:** `fallback-llm`
    **Expected result:** `Fallback endpoint` displays `fallback-llm`.
12. **Action (Administrator):** Select the tool set.
    **Test data:** `research-readonly@2`
    **Expected result:** `Tool set` displays `research-readonly@2`.
13. **Action (Administrator):** Select the limits policy.
    **Test data:** `interactive-default@4`
    **Expected result:** `Limits policy` displays `interactive-default@4`.
14. **Action (Administrator):** Select `Create agent version` once.
    **Test data:** visible action `Create agent version`
    **Expected result:** Agent version `1` is published and displayed as read-only.
15. **Observation (Administrator):** Inspect the published version summary.
    **Test data:** fixture reference IDs and versions
    **Expected result:** The exact endpoint IDs, endpoint versions, `research-readonly@2`, and `interactive-default@4` are shown.
16. **Action (Administrator):** Select `Edit as new draft`.
    **Test data:** visible action `Edit as new draft`
    **Expected result:** A new editable draft opens while published version `1` remains unchanged.

## Cleanup

Restore the named fixture snapshot through the authorised CAP-02 reset command
and retain its reset receipt. Do not delete the published version manually.

## Required evidence and oracle

- screenshots of steps 14 through 16;
- exported safe version metadata containing exact IDs/versions but no credentials;
- candidate SHA, fixture checksum, environment, tester, UTC times, and attempt;
- pass only if the published version is immutable and all references remain exact.
