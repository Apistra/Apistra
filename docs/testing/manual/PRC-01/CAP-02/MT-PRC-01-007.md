## Objective

Prove that an Administrator can store and replace a project secret while the
value remains write-only and all visible records expose only an opaque
project-scoped reference and safe metadata.

## Preconditions

- The unchanged CAP-02 staging candidate is identified by `CAPABILITY_CANDIDATE_SHA`.
- `FX-PRC-01-CAP02-CATALOG` is applied and its receipt/checksum is recorded.
- A fresh browser profile can resolve `STAGING_SIGN_IN_URL`.
- `STAGING_ADMIN_PASSWORD`, `CAP02_TEST_SECRET_PRIMARY`, and
  `CAP02_TEST_SECRET_ROTATED` resolve only in the protected execution context.

## Procedure

1. **Action (Logged-out visitor):** Open `STAGING_SIGN_IN_URL` in the fresh browser profile.
   **Test data:** `STAGING_SIGN_IN_URL`
   **Expected result:** The page title is `Sign in`.
2. **Action (Logged-out visitor):** Enter the Administrator username in `Username`.
   **Test data:** `admin.alpha`
   **Expected result:** `Username` contains exactly `admin.alpha`.
3. **Action (Logged-out visitor):** Enter the protected password in `Password`.
   **Test data:** protected parameter `STAGING_ADMIN_PASSWORD`
   **Expected result:** `Password` displays only masked characters.
4. **Action (Logged-out visitor):** Select `Sign in`.
   **Test data:** visible action `Sign in`
   **Expected result:** The page title is `Project overview`.
5. **Action (Administrator):** Select project `Atlas Research`.
   **Test data:** project key `ATLAS`
   **Expected result:** `Atlas Research` is displayed as the current project.
6. **Action (Administrator):** Select navigation item `Secrets`.
   **Test data:** visible navigation label `Secrets`
   **Expected result:** The page title is `Secret references`.
7. **Action (Administrator):** Select `Add secret`.
   **Test data:** visible action `Add secret`
   **Expected result:** The form renders `Name`, `Purpose`, and masked `Secret value`.
8. **Action (Administrator):** Enter the secret name in `Name`.
   **Test data:** `provider-primary`
   **Expected result:** `Name` contains exactly `provider-primary`.
9. **Action (Administrator):** Enter the purpose in `Purpose`.
   **Test data:** `Primary generative endpoint credential`
   **Expected result:** `Purpose` contains exactly the supplied purpose.
10. **Action (Administrator):** Enter the protected secret in `Secret value`.
    **Test data:** protected parameter `CAP02_TEST_SECRET_PRIMARY`
    **Expected result:** `Secret value` displays only masked characters.
11. **Action (Administrator):** Select `Store secret`.
    **Test data:** visible action `Store secret`
    **Expected result:** The status message is `Secret stored. The value cannot be viewed again.`
12. **Observation (Administrator):** Inspect the stored `provider-primary` entry.
    **Test data:** secret name `provider-primary`
    **Expected result:** The entry shows an opaque reference ID, status, timestamps, and envelope version without the secret value.
13. **Action (Administrator):** Select `Replace value` for `provider-primary`.
    **Test data:** visible action `Replace value`
    **Expected result:** A masked replacement field is displayed without the current value.
14. **Action (Administrator):** Enter the rotated protected secret in the replacement field.
    **Test data:** protected parameter `CAP02_TEST_SECRET_ROTATED`
    **Expected result:** The replacement field displays only masked characters.
15. **Action (Administrator):** Select `Store secret`.
    **Test data:** visible action `Store secret`
    **Expected result:** A new active secret version is confirmed without disclosing either value.

## Cleanup

Restore the named fixture snapshot through the authorised CAP-02 reset command
and retain its reset receipt. Do not copy either protected value into evidence.

## Required evidence and oracle

- screenshots of steps 7, 11, 12, and 15 with all sensitive fields masked;
- candidate SHA, fixture revision/checksum, environment, tester, UTC times, and attempt;
- secret-reference identifier and safe audit-event identifiers only;
- pass only if no protected value appears and replacement creates a distinct version.
